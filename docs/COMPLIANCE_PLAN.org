* Headline change: the =foundation= crate

The template now ships a =rust-template-foundation= crate (plus a
sibling =rust-template-foundation-derive= proc-macro crate) that
derived projects consume as a *Cargo git dep* and as a *Nix flake
input*.  It absorbs everything that used to live duplicated in each
spawned repo.

What foundation now owns:

- =auth/= — OIDC login / callback / logout, =require_auth= middleware,
  *new* JWT bearer-token validation for service callers.
- =server/runner.rs= — =Server<S>= builder, =BaseServerState=,
  =ServerApp= trait, =ServerRunConfig=, =impl_server_state!= macro.
- =server/health.rs=, =server/metrics.rs=, =server/openapi.rs=,
  =server/me.rs=, =server/spa.rs=, =server/shutdown.rs=, =server/systemd.rs= —
  the entire web base.
- =config.rs= — XDG config-file discovery, =find_config_file=,
  =credential_secret_path= (LoadCredential), =CommonConfigFile=,
  =ConfigFileError=.
- =logging.rs= — =LogLevel=, =LogFormat=, =init_logging=.  The
  template lib crate now just re-exports these.
- =MergeConfig= proc-macro — generates =CliRaw=, =ConfigFileRaw=, and
  the merge into =Config= from a single struct annotation.  Supports
  =extra_cli= / =extra_file= flatten escapes, =subcommand= field kind
  (=788f787=), =extra_error= attribute (=1269b8a=).
- =#[foundation_main]= proc-macro — wraps your =async fn main(config:
  Config, server: Server) -> Result<...>= and inserts CLI parse,
  config resolve, logging init, OIDC discovery, listener bind, systemd
  notify, graceful shutdown.
- Nix helpers — =mkRustProject= (workspace flake outputs),
  =mkNixosService=, =mkDarwinService=, exposed from the foundation
  flake's =lib=.
- Reusable GitHub Actions workflows — =reusable-ci.yml=,
  =reusable-publish.yml=, =reusable-branch-protection.yml=,
  =reusable-dependabot-automerge.yml=.

The net effect on the template's =template/= subtree (what derived
projects mirror): ≈2400 LOC removed, ≈700 added across 36 files.

* Compliance plan

Phased so each step leaves the workspace green (=cargo build --workspace= +
=cargo test --workspace= passing inside =nix develop=).  Each phase is
one or two commits.

** Phase 1 — Wire the foundation

1. Add =rust-template-foundation= to =[workspace.dependencies]=.
2. Add =foundation= flake input + thread it through =outputs=.
3. =cargo build --workspace= to confirm resolution.

No source changes yet; this is just plumbing.

** Phase 2 — Lints and toolchain hygiene

1. Add =[workspace.lints.clippy]= deny block + =clippy.toml=.
2. Add =[lints] workspace = true= to each crate's =Cargo.toml=.
3. Eliminate the 21 =.unwrap()= / =.expect()= sites in shipping code.
   Strategy: replace with =?= via semantic =thiserror= variants, or
   move literal validation to =const= / proc-macro per the new
   =llms.org= guidance.
4. =cargo clippy --workspace -- -D warnings= must pass.

This phase is the largest single body of work.  It also provides
forcing-function value: every =.unwrap()= replaced becomes a real
named error variant.

** Phase 3 — CLI migration

1. Replace =crates/cli/src/main.rs= with the =#[foundation_main]=
   shape.
2. Rewrite =crates/cli/src/config.rs= using =MergeConfig= with the
   =subcommand= field kind for compendium/encounter/dice subcommands.
3. Delete =crates/cli/src/logging.rs=.
4. Verify subcommand UX: =ezpz-dndz-cli compendium list=, etc. still
   work end-to-end.

** Phase 4 — Server migration

1. Rewrite =crates/server/src/web_base.rs= around
   =impl_server_state!=; keep app stores on =AppState=, drop the
   registry/counter/oidc/frontend_path fields (now in =base=).
2. Rewrite =crates/server/src/config.rs= using =MergeConfig= with
   =extra_cli= / =extra_file= for the OIDC-style fields and the
   ezpz-specific paths (=data_dir=, =dice_history_path=,
   =compendium_path=, =compendium_saves_path=, =encounter_path=,
   =encounter_saves_path=).  Implement =ServerApp::server_run_configs=.
3. Replace =crates/server/src/main.rs= with the
   =#[foundation_main]=-style entry; attach app routes via
   =Server::merge(ApiRouter)=.
4. Delete =crates/server/src/{auth,logging,systemd}.rs=.
5. Verify HTTP integration tests still pass; manual smoke =/healthz=,
   =/metrics=, =/scalar=, =/api-docs/openapi.json=, OIDC roundtrip,
   compendium and encounter routes.

** Phase 5 — Library slimming

1. Slim =crates/lib/src/logging.rs= to a foundation re-export (or
   remove the file and update imports).
2. Update =crates/lib/src/lib.rs= re-exports.

** Phase 6 — Nix + CI

1. Rewrite =flake.nix= around =foundation.lib.mkRustProject=.
2. Rewrite =nix/modules/{nixos,darwin}-server.nix= around the

3. Verify =nix build .#cli=, =nix build .#server=, =nix flake check=.

5. Add =.github/dependabot.yml= and =dependabot-automerge.yml=.
6. Resolve the CI question (see [[*Open questions]]).

1. Sync =llms.org= with the template version (or replace and re-add

2. Update CLAUDE.md to reference the new =unwrap=/=expect= rule (or

4. =nix develop --command cargo build --workspace= and

* Open questions

These need a human decision before Phase 6 (or earlier where flagged):

1. *CI workflow.*  The reusable =reusable-ci.yml@main= is Rust-only.
   ezpz needs Elm =elm make= and =elm-test= steps.  Options:
   - (a) Keep our hand-rolled =ci.yml= and accept this single
     non-compliance.
   - (b) Call =reusable-ci.yml= and add a follow-up Elm job in the
     same workflow.
   - (c) Contribute Elm support upstream into the reusable.

2. *Env var rename.*  Adopting =ezpz-dndz_log_level= etc. breaks any
   systemd unit / justfile that sets the old =LOG_LEVEL= names.
   Options: cut over cleanly, or keep aliases via =extra_cli= for one
   release.

3. *=lib= crate logging file.*  Slim to a re-export, or delete the
   file outright and update call sites?  Either is compliant; the
   second is cleaner.

4. *=.unwrap()= cleanup ordering.*  Phase 2 does it before the
   CLI/server rewrites so the rewrites land on lint-clean ground.
   Alternative: do it after the rewrites since some sites disappear
   in the migration anyway.  Phase-2-first reduces churn risk; Phase-2-after
   avoids touching code about to be deleted.
