* DONE Relational storage migration (SQLite + Postgres, no JSON stores)

Replace every =JsonFileStore=-backed store with a fully relational schema served
by sqlx over two interchangeable backends: SQLite (default, at
=<data_dir>/ezpz-dndz.db= — zero-ops dev and small deploys) and PostgreSQL
(=--database-url postgres://…= for hosted scale to hundreds of users).  No
document stores: no JSON/JSONB columns anywhere; the Elm wire formats are
normalized into real tables, with the server-side codecs mirroring the Elm
=*.Wire= modules (including their legacy-shape leniency, which the one-shot
import needs).

Constraints: the HTTP API shapes stay byte-compatible (the Elm frontend is
untouched; existing integration tests pass unmodified); storage primitives live
in the lib crate; semantic thiserror errors; portable DDL (TEXT ids, INTEGER
timestamps, =$n= placeholders, which SQLite also accepts).  On first boot
against an empty database the server imports the legacy JSON files from the data
dir one-shot (marker table suppresses re-runs); the JSON files are left in place
as the rollback copy.

Phases: (1) db core + users + dice history, (2) the five per-user preset stores,
(3) compendium (user creatures, groups, saves), (4) encounters (live
+ named saves, shared schema keyed by slot), (5) retire JsonFileStore + CLI port
  + backup script + docs, (6) live Postgres verification.

Accepted tradeoff, noted for the record: the server previously round-tripped
most payloads as opaque JSON so the frontend owned those schemas outright;
normalization means future Elm wire changes to persisted shapes need a matching
server migration.

* TODO Migrate the frontend off modal dialogs

External review asked for a UI that never hides the encounter queue behind a
modal.  The analysis and migration plan live in [[file:docs/MODAL_MIGRATION.org][docs/MODAL_MIGRATION.org]].  In
progress on the =modal-migration-inline= branch: the Surface rename, the inline

no picker UI to anchor, so that tier is empty and closed rather than built.  The
route tier still owes the compendium's edit / paste / group / lore forms plus
=TreasureTable=, and the toast-plus-undo conversions remain.

* TODO Teach the Save Chain editor the rules its presets need

The bundled Save Chain presets were checked against the 2024 rules (SRD 5.2.1),
and [[file:docs/SAVE_CHAIN_PRESETS.org][docs/SAVE_CHAIN_PRESETS.org]] records what each can only approximate today.
The settings that would close those gaps, roughly in order of how many presets
each unlocks:

1. A duration on an applied effect — until the end of the target's next turn,
   until the start of the caster's next turn, a countdown, one minute.  The
   Condition editor already offers these; a chain applies everything as manual.
2. A repeat save that escalates on a failure instead of merely continuing, or
   deals damage again.
3. A repeat save triggered by an event — taking damage, ending a turn out of the
   caster's sight — rather than a turn boundary.
4. Area effects that re-save every turn a creature stays inside, applying a
   one-turn condition on a failure rather than a lasting one.
5. Linked effects that end together on one save.
6. A timed success-side immunity that expires on its own.
7. A hit-point-maximum reduction on a failed save.
8. Threshold outcomes — a drop to 0 hit points under a ceiling, and automatic
   failure for a creature type.
