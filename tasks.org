* DONE Relational storage migration (SQLite + Postgres, no JSON stores)

Replace every =JsonFileStore=-backed store with a fully relational schema served
by sqlx over two interchangeable backends: SQLite (default, at
=<data_dir>/ezpz-dndz.db= — zero-ops dev and small deploys) and PostgreSQL
(=--database-url postgres://…= for hosted scale to hundreds of users).  No
document stores: no JSON/JSONB columns anywhere; the Elm wire formats are
normalized into real tables, with the server-side codecs mirroring the Elm
=*.Wire= modules (including their legacy-shape leniency, which the one-shot
import needs).

Constraints: the HTTP API shapes stay byte-compatible (the Elm frontend is
untouched; existing integration tests pass unmodified); storage primitives live
in the lib crate; semantic thiserror errors; portable DDL (TEXT ids, INTEGER
timestamps, =$n= placeholders, which SQLite also accepts).  On first boot
against an empty database the server imports the legacy JSON files from the data
dir one-shot (marker table suppresses re-runs); the JSON files are left in place
as the rollback copy.

Phases: (1) db core + users + dice history, (2) the five per-user preset stores,
(3) compendium (user creatures, groups, saves), (4) encounters (live
+ named saves, shared schema keyed by slot), (5) retire JsonFileStore + CLI port
  + backup script + docs, (6) live Postgres verification.

Accepted tradeoff, noted for the record: the server previously round-tripped
most payloads as opaque JSON so the frontend owned those schemas outright;
normalization means future Elm wire changes to persisted shapes need a matching
server migration.

* TODO Drop the cross-build source wrapper once the foundation keeps the source

Each variant helper in ~rust-template~ builds its crane arguments as ~commonArgs
// {src = craneLib.cleanCargoSource self; ...}~, so the source a project passes
is discarded and only Cargo files survive.  This workspace extends that filter
to keep =crates/lib/data/bundled-creatures.json=, which the server crate embeds
with ~include_str!~, so every release binary failed to compile from v0.2.0 until
=flake.nix= put the filtered source back on the finished derivations.

The fix belongs upstream, where the helpers should read ~commonArgs.src or
(craneLib.cleanCargoSource self)~ rather than overwriting it — every downstream
project that filters its source meets the same wall, and =CONTRIBUTING.org= says
these helpers need no per-crate configuration, which the local wrapper makes
untrue.  rust-template carries that shape from v0.121.0, so the wrapper comes
out on the ~foundation~ bump that reaches it, alongside
[[*Drop the cross-build environment wiring once the foundation supplies it]].

* TODO Drop the cross-build environment wiring once the foundation supplies it

The variant helpers leave parts of the build environment they need unset, and
=flake.nix= fills those in for them.

~mkMuslPackages~ selects its target with ~CARGO_BUILD_TARGET~ and nothing else,
where its sibling helpers each also name a ~CC~ and ~CXX~ for the target they
build.  A dependency whose build script compiles C is therefore compiled against
the host's glibc and cannot link against musl, which is where the bundled SQLite
that sqlx carries left the static release binaries.  The helper should name them
itself; the glibc-floored variant writes the same pair of zig wrappers a few
lines away, so only the target triple differs.

The portable-glibc helper compiles C through zig without turning zig's
undefined-behaviour checks off, where the macOS helper's compiler wrapper does
turn them off.  Nothing supplies the handlers those checks call, so a proc-macro
library links with them undefined and the compiler cannot load it back.  That
variant builds for the host's own triple, which is why the target's toolchain
reaches a host artifact at all.  =flake.nix= appends the switch through the
flags the ~cc~ crate reads, the helper's own wrapper not being overridable.

The helpers that build through cargo-zigbuild leave crane's dependency check
pass running under an environment their build command does not share, since
cargo-zigbuild supplies its own linker to its own invocation alone.  Cargo reads
that as a reason to re-run every build script, and the bundled SQLite cannot
replace the read-only bindings its first run copied out of the vendor store.
Those helpers already skip the test phase because a cross variant repackages
sources the native build has gated, and the check pass is redundant for the same
reason.

Propose both against rust-template, then delete the local wiring on the
~foundation~ bump that carries them — the same bump that clears
[[*Drop the cross-build source wrapper once the foundation keeps the source]].

* DONE Give Save Chain effects durations, failed-save outcomes, and immunities

Three of the settings the preset review asked for.  An effect's duration uses
the Condition editor's picker over a preset-relative form — the target, the
active creature, or a name — that settles at apply time; a repeat save can turn
the condition into another or deal damage again on a failure, from either
editor; and a chain can grant a timed immunity on success that it then honours.
Part of [[*Teach the Save Chain editor the rules its presets need]].

* DONE Give Save Chain effects event-triggered saves, areas, companions, and drain

The rest of the settings the preset review asked for, save one.  A repeat save
can wait on an event rather than a turn boundary: an "ask at end of turn" timing
flashes the chip for the GM to roll when the rule's trigger applied, and a hit
can flash the chip or roll the save outright, with advantage where the rules
grant it.  An area chain marks each target with a chip that rolls the chain
again at the chosen phase of every turn and applies the outcome, with a 🎲 for a
creature entering mid-turn and a × for one leaving.  An effect can name a
companion condition that ends with it, and an outcome can drain — damage that
lowers the hit point maximum by the amount dealt.  Part of
[[*Teach the Save Chain editor the rules its presets need]].
