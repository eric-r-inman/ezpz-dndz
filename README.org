A D&D combat encounter manager and monster database — a server with an
Elm frontend for running combat at the table, plus a CLI for managing
the underlying monster catalog. Creature stat blocks, and some other content,
sourced from D&D System Reference Document 5.2.1, and information available
in public forums.

* Introduction

Running combat at a D&D table involves a lot of bookkeeping: initiative
order, hit points, conditions, legendary actions, lair effects, and the
ever-present need to look up a monster's stat block.  ~ezpz-dndz~ is a
project I've been working on for my own D&D games; it aims to take 
that bookkeeping off my plate so I can focus on the narrative.

The project ships two binaries and a shared library:

- ~ezpz-dndz-server~ :: HTTP server hosting the encounter-manager UI
  and the monster database REST API.
- ~ezpz-dndz-cli~ :: Terminal companion for importing, querying, and
  curating the monster catalog without spinning up the server.
- ~ezpz-dndz-lib~ :: Shared domain types (creatures, encounters,
  initiative, conditions) and persistence logic.

* Running it locally

Personal use only — see [[*License][License]].

** Prerequisites

- [[https://nixos.org/download/][Nix]] with flakes enabled.  Everything else (Rust toolchain,
  Elm, treefmt, ~just~, ~elm-test~) is pulled into the dev shell
  automatically.
- ~git~.  That's the whole list.

You don't need Rust, Elm, or any toolchain installed system-wide.
The Nix dev shell provides them at the versions the project pins.

** First-run setup

#+begin_src sh :exports code
git clone https://github.com/eric-r-inman/ezpz-dndz
cd ezpz-dndz
nix develop --command cargo build --workspace
nix develop --command bash -c \
  "cd frontend && elm make src/Main.elm --output public/elm.js"
#+end_src

The first ~nix develop~ pulls a few hundred MB of toolchain (one-
time); subsequent invocations are instant.  The ~cargo build~
output goes under ~target/~ (gitignored); the Elm bundle lands at
~frontend/public/elm.js~ (also gitignored).

If you have ~just~ on your PATH, ~just dev~ does the elm build
and starts the server in one step — see [[*Day-to-day]] below.

** Day-to-day

Start the server with the dev shell's tooling:

#+begin_src sh :exports code
just dev
#+end_src

That rebuilds the Elm bundle, launches ~ezpz-dndz-server~ on
~http://127.0.0.1:4040~, and opens it in your default browser
(~just serve~ is the same minus the browser-open).  Stop with
Ctrl-C.

If you don't have ~just~, the equivalent long form is:

#+begin_src sh :exports code
nix develop --command bash -c \
  "cd frontend && elm make src/Main.elm --output public/elm.js"
nix develop --command \
  cargo run -p ezpz-dndz-server -- \
    --listen 127.0.0.1:4040 \
    --base-url http://127.0.0.1:4040 \
    --frontend-path frontend/public
#+end_src

Persistence lives in whatever ~--data-dir~ resolves to.  Without
the flag, the server writes its JSON store files into the current
directory (~./users.json~, ~./encounter.json~, etc., all
gitignored).  For a clean scratch dir, pass ~--data-dir
/tmp/ezpz-scratch~ on the ~cargo run~ line.

** Trying it out

Open ~http://127.0.0.1:4040~.  You'll boot into anonymous mode —
your work persists in browser ~localStorage~, no account
required.  A banner at the top reminds you that anonymous data is
local-only.

To switch to a server-backed account, click *Sign in* in the
top-right and *Create one* to register.  Anything you built up
in anonymous mode (encounters, custom creatures, named saves)
migrates into the new account automatically.

** Running the tests

Cargo + Elm test suites:

#+begin_src sh :exports code
nix develop --command cargo test --workspace
cd frontend && nix develop --command elm-test
#+end_src

Or the one-shot via ~just~:

#+begin_src sh :exports code
just test
#+end_src

The compendium-CLI subcommands sit under ~ezpz-dndz-cli~:

#+begin_src sh :exports code
nix develop --command cargo run -p ezpz-dndz-cli -- --help
#+end_src

Operator-only subcommands (currently: ~users reset-password~
for resetting a forgotten password against a local data dir)
live under ~users~ — see ~--help~ for the full list.

** When something doesn't work

- ~nix develop~ hangs or fails on the first run :: this is the
  toolchain download.  Wait it out the first time; subsequent
  shells reuse the cached store paths.
- ~elm make~ complains about missing packages :: delete
  ~frontend/elm-stuff/~ and re-run.  The package index
  occasionally needs a fresh cache.
- Port 4040 already in use :: another instance is running, or
  another app squatted the port.  Either kill it or pass
  ~--listen 127.0.0.1:4041~ to the ~cargo run~ line above.
- Server logs "compendium split migration: ... ClaimUserMissing"
  :: you have data from an earlier version that the new per-user
  compendium layer doesn't know who owns.  Register your account
  in the UI, stop the server, and restart with
  ~--compendium-claim-user <your-email>~.  See
  ~docs/DEPLOY.org~ for the longer migration story.
