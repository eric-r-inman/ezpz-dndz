#+title:     Changelog
#+language:  en

* Upcoming

** Architecture

- Split the Elm frontend into two modules: ~Encounter.elm~ (domain
  layer — types, seed data, turn logic) and ~Main.elm~ (application
  shell + view code).  Domain code does not import rendering
  primitives.  See [[file:docs/ARCHITECTURE.md][docs/ARCHITECTURE.md]] for the full discussion and
  the discipline that goes with it.

** Frontend

- Introduce real turn tracking.  =Encounter.nextTurn= advances the
  active creature in initiative order and increments =round= on wrap.
  Wired to the *⏭ Next Turn* button in Encounter Controls.
- Encounter title bar shows live =round=, active creature name, and
  active creature HP (state icons and the conditions summary stay
  placeholder for now).
- Brand mark dropped; title renders as "eZpZ-dndZ" in plain text
  rather than the gradient mark + wordmark.
- Right-arrow on a creature card now jumps the active marker to that
  creature without advancing the turn (no round bump, no turn-
  progression hooks).  Wires =Encounter.setActive=, distinct from
  =Encounter.nextTurn=.

** Dice roller

- New ~Dice.elm~ domain layer: notation parser (=1d6=, =2d8+3=,
  compound =1d8 + 2d6=, damage-tagged =2d6+3 fire damage=, and the
  stat-block average wrap =7 (1d8 + 3)=); random-roll generators for
  standard / advantage / disadvantage / coin; bounded in-memory
  history (max 30, matching the JS roller).
- New dice modal in =Main.elm=, wired to the existing *🎲 Roll*
  button.  Free-text expression input with Enter-to-roll, count and
  modifier sliders, rainbow d4–d100 face buttons, advantage /
  disadvantage / coin-flip, history list with re-roll and clear.
  Closes on backdrop click, ✕, or Esc.
- Stat-block traits in the Compendium now have clickable inline
  dice notation (=Dice.scan= splits text into literal runs and
  recognized formulas); clicking rolls the formula and opens the
  modal in one gesture.
- Server-side history persistence so the dice log survives reloads
  without any handwritten JS.  =GET / POST / DELETE /api/dice/history=
  are handled in =crates/server/src/dice.rs=, persisting to
  =dice-history.json= (configurable via =--dice-history-path=) with
  atomic-rename writes and an async mutex around the file.

** Production prep

- New =--data-dir= / =DATA_DIR= config option (default: cwd).  All
  runtime persistence will derive from this so a deployment only has
  to bind-mount one directory.  =--dice-history-path= now defaults to
  =<data_dir>/dice-history.json= (still overridable explicitly).
- =config.example.toml= grows commented-out blocks for =data_dir=,
  =dice_history_path=, and the OIDC fields, with a pointer at
  [[file:docs/ARCHITECTURE.md][docs/ARCHITECTURE.md]] for deployment notes.
- New [[file:docs/ARCHITECTURE.md][docs/ARCHITECTURE.md]] section "Production deployment" plus
  "Planned data model".  New [[file:docs/ROADMAP.md][docs/ROADMAP.md]] tracks the upcoming
  feature pipeline (compendium read API, encounter save/load,
  per-user dice history, SQLite migration, OIDC polish, real-time
  co-DM mode).

** HP Change engine

- New ~HpChange.elm~ pure module implementing 5e HP arithmetic for
  damage / heal / temp HP through a single ~apply~ entry point so
  the three buttons can't drift apart.  Damage absorbs temp HP
  first (with optional ~ignoreTemp~ override); heal caps at maxHP
  and clears death-save tracking when reviving from 0; temp HP
  follows the replace-if-higher rule.  ~bloodied~ is now auto-
  derived from current vs. max HP.
- Creature gains a ~tempHp : Int~ field; the row 2 HP display shows
  it as a "+N" chip when nonzero.
- The Damage / Heal / Temp HP buttons in card row 3 are wired to a
  shared modal (~viewHpChangeModal~) with two input modes:
  - *Manual*: enter the amount as a number; live preview shows the
    before / after HP.
  - *Roll dice*: enter a Dice expression (using the same parser as
    the dice modal); Apply rolls and applies in one shot, also
    logging the roll to the dice history (POST /api/dice/history).
- Damage gets an "Ignore temporary HP" checkbox; heal and temp HP
  show only the amount input.

** Initiative manager

- Clicking the blue init-circle on a creature card opens an
  Initiative Manager modal with three sections: *Quick Sort
  Encounter* (re-orders the queue by descending initiative via
  =Encounter.sortByInitiative=), *Auto-roll Initiative* (rolls
  =1d20 + initiativeBonus= for the click target / all / selected
  via =Dice.batchRollCmd=), and *Custom Initiative* (manual value
  apply for target / selected).
- New ~Encounter.sortByInitiative=, ~Encounter.moveUp=, and
  ~Encounter.moveDown= functions.  =activeName= is preserved across
  sorts so re-sorting mid-combat doesn't reset whose turn it is.
- New ~Dice.batchRollCmd= rolls a list of expressions in a single
  Cmd, sharing one timestamp + one sequenced seed-step.  This
  prevents the "8 creatures all roll the same number" collision
  that would happen with N per-call =rollCmd= invocations in the
  same millisecond.
- =Creature= gains ~initiativeBonus : Int=.  Seed values are
  set per creature (Lyra +5, Brakka -1, Vex/Goblins +2, Shaman
  +1, Sentinel -1, Wisp +3).
- Up / down arrows on each card's left rail now move the creature
  one slot up or down in the queue (via =moveUp= / =moveDown=)
  without touching initiative.  A subsequent =sortByInitiative=
  wipes the manual order — that's the documented contract.
- Selection checkbox in the row 1 left rail is now interactive.
  Plain click toggles a single creature; *Shift+click* selects all
  if any are unselected, deselects all if every creature is
  selected.  Implemented via =preventDefaultOn "click"= so model
  is the single source of truth for the checkbox state.

** Dice source tagging

- =Dice.Roll= gains a =source : Source= field where
  =Source = { feature : String, target : Maybe String }=.  The
  dice history renders a chip per entry — "Damage → Brakka, Ogre
  Brute", "Heal → Lyra Vale (PC)", "Initiative → Goblin Boss",
  "Stat block → Brakka, Ogre Brute".  The chip is hidden for the
  default ~manualSource~ since the dice modal's own buttons make
  the context obvious.
- All ~Dice.*Cmd~ entry points (~rollCmd~, ~advantageCmd~,
  ~disadvantageCmd~, ~coinCmd~, ~batchRollCmd~) take a Source.
  =Dice.rollWithTime= stamps it onto the rolled Roll so callers
  don't have to remember to overwrite afterwards.
- JSON encode / decode round-trip the source.  The decoder uses
  =Decode.oneOf= with =manualSource= as a fallback so legacy
  =dice-history.json= entries from before this field continue to
  load.
- =DiceRerun= preserves the original entry's source so a re-rolled
  "Damage → Brakka" stays labelled the same way.

** Card row 2 HP polish

- New ~Model.hpChangeLog : List HpChangeEntry= (capped at 10)
  records each application via the HP-change modal.  Rendered as
  a list of "[Damage] Brakka 13 27/59 → 14/59" rows at the
  bottom of the modal — shared across the Damage / Heal / Temp
  HP verbs so the GM sees recent table context regardless of
  which modal is open.
- Click-to-edit current and max HP on the card.  Clicking either
  value swaps the span for an autofocused ~<input>~; Enter or
  blur commits, Esc cancels.  Commits go through new
  ~HpChange.setCurrentHp= and ~HpChange.setMaxHp= helpers that
  clamp current to =0..maxHp= and max to =>= 1=, dragging
  current with it if it would otherwise exceed.  =bloodied= is
  auto-recomputed.
- Temp HP readout in card row 2 now matches the rest of the HP
  text in size and color — drops the pill background, uses the
  same blue as the Temp HP button.  Reads inline as "38/42 +5".
- Card row 3 colored buttons (Damage / Heal / Temp HP /
  Condition/Effect) lightened ~10% from their original saturated
  hues; all label text is now white for legibility.

** Dice modal polish

- Added a ❌ reset button to the right of the Modifier field;
  clicking restores count → 1 and modifier → 0 in one click.
- Modifier field now allows transient negative input ("-" alone,
  "-5", "-12") without the controlled input clobbering the user's
  characters between keystrokes.  =DiceUi= now carries a
  =modifierText : String= alongside the parsed integer.

** Encounter title bar

- Active-creature HP in the title bar now uses the same shared
  =.hp-display*= classes as the card row 2, so the green / muted
  / blue palette stays in lockstep.  Temp HP shows inline as
  "+N" when nonzero.

** Initiative: Advantage sister buttons

- Each Auto-roll button in the Initiative Manager modal now has a
  green *Advantage* sibling on its right that rolls 2d20-keep-
  highest + bonus instead of 1d20 + bonus (5e advantage).
- =Dice.batchRollCmd= is now generic over the per-spec generator
  (~Random.Generator Roll~ instead of ~Expression~), so callers
  pick whichever generator they want and mixed-mode batches are
  fine.
- Replaced the three separate Msgs (=InitiativeAutoRollTarget /
  All / Selected=) with one parameterized
  =InitiativeAutoRoll RollScope RollMode=.  Future Disadvantage
  drops in as a third =RollMode= constructor without churning
  the Msg shape.

** Surprise rule (turn skip)

- =Encounter.nextTurn= now honors the per-creature ~surprised~
  flag.  When the queue would make a surprised creature active,
  the creature is skipped and the flag is cleared in the same
  step — their next turn after that happens normally.  A run of
  consecutive surprised creatures all get skipped on one Next
  Turn click.  Defensive iteration cap of ~length creatures~
  guards against an all-surprised queue spinning.  Implemented
  as the first real "beginning of turn" hook composed around
  the existing queue walk.
