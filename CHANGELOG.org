** Empty default + auto-persist live encounter

- ~Encounter.empty~ replaces ~Encounter.initialEncounter~ as
  the running app's boot state.  The 7 mock seed creatures
  (Lyra Vale, Brakka, etc.) stop appearing.  ~initialEncounter~
  is kept as a test fixture only.
- New backend route group at ~/api/encounter~ (GET / PUT,
  opaque ~serde_json::Value~ storage), backed by
  ~EncounterStore~ wrapping ~JsonFileStore~ in
  ~crates/server/src/encounters/~.  New ~--encounter-path~ /
  ~ENCOUNTER_PATH~ flag; defaults to ~<data_dir>/encounter.json~.
- New ~Encounter.Wire~ Elm module with full encode / decode
  for the Encounter → Creature → Condition / Duration /
  TurnPhase / TurnTarget / SaveToEnd / AutoRollMode /
  SaveNotice / Cover / DeathSaves / Timer tree.  Decoder
  tolerates missing fields with sensible defaults so a future
  schema bump that adds a field doesn't break the legacy
  load path.
- ~Main.elm~'s top-level ~update~ is now a thin wrapper over
  ~updateInner~ that diffs ~model.encounter~ before/after
  each Msg and batches a ~persistEncounterCmd~ when it
  mutated.  Save failures surface as a red toast; success
  is silent.
- Boot path: ~init~ dispatches ~fetchEncounterCmd~ alongside
  the existing dice-history + compendium fetches.  A server
  ~null~ response reads as "use the empty default"; otherwise
  the persisted encounter replaces the empty default.

** Bundled creatures: 8 SRD-derived, version-aware ADD-ONLY merge

- Replaced the 5 placeholder creatures in
  ~crates/lib/data/bundled-creatures.json~ with 8 fully-detailed
  SRD-derived stat blocks: Goblin (CR 1/4), Skeleton (CR 1/4),

  ~BundleSeedParseError~.

  rewrites the creature's id / source / timestamps, appends
  to ~bundled-creatures.json~, and bumps ~BUNDLED_VERSION~.
- 5 new integration tests in ~crates/server/tests/
  compendium_bundle_test.rs~ covering fresh install,

** Compendium parser: D&D Beyond export format + dice-scan trailing punctuation

- Real-world Adult Blue Dragon paste from D&D Beyond exposed
  seven format gaps the canonical-SRD parser missed.  All
  fixed and locked in by 17+ assertions in the new Blue
  Dragon fixture test:
  - Short-form prefixes (~AC~, ~HP~, ~CR~, bare ~Immunities~
    etc.) accepted alongside the long forms.
  - Tab-separated ability rows (~STR\t25\t+7\t+7~) parsed via
    a new ~LineAbilityRow~ variant; ~Mod\tSave~ header rows
    skipped via ~LineIgnore~.
  - ~Traits~ as a section header.
  - ~AC 19    Initiative +10 (20)~: stripped the Initiative
    suffix before parens-extraction so the AC note doesn't
    grab the initiative roll-result.
  - CR ~16 (XP 15,000, or 18,000 in lair; PB +5)~: parses
    out CR + XP + PB from a single combined line.
  - ~Senses Blindsight 60 ft., Darkvision 120 ft.; Passive
    Perception 22~: ~;~ now treated as an alias for ~,~.
  - Trailing lore detection: when a feature ends with a
    period and the next line looks like prose, commit the
    feature, switch to lore mode, and dump the rest into a
    single ~Description~ custom section instead of greedily
    extending the last action.  Tightened to require ~pending
    = Just complete~ specifically, so a long opening trait
    body right after a section header doesn't trip it.
- Lair-section parsing: fuzzy ~<X> Lair~ / ~<X> Lairs~ /
  ~<X> Regional Effects~ heading detection (title-case +
  short-line gates against false positives), works even
  mid-lore-mode.  ~parkPreamble~ rewritten so ~LairSection~ /
  ~RegionalSection~ / ~LegendarySection~ populate the
  matching ~description~ field instead of always going into
  ~customSections~.
- Two latent ~Dice.scan~ bugs fixed.  Both blocked clickable
  inline dice in any prose context (~roll 1d20.~ /
  ~2d4 × 10 feet~):
  - ~Parser.int~ treats trailing ~.~ as a malformed-float
    committed error.  Replaced with bare-digit chomping
    (~chompIf isDigit |. chompWhile isDigit~) inside
    ~diceInline~.
  - The optional ~+N~ modifier branch's ~Parser.spaces~
    greedily committed on a trailing space, then the missing
    sign caused a committed failure the surrounding ~oneOf~
    couldn't unwind.  Wrapped in ~Parser.backtrackable~.

** Server compliance: semantic dice errors + OpenAPI coverage (Phase 1)

** HP Change engine

- New ~HpChange.elm~ pure module implementing 5e HP arithmetic for
  damage / heal / temp HP through a single ~apply~ entry point so
  the three buttons can't drift apart.  Damage absorbs temp HP
  first (with optional ~ignoreTemp~ override); heal caps at maxHP
  and clears death-save tracking when reviving from 0; temp HP
  follows the replace-if-higher rule.  ~bloodied~ is now auto-
  derived from current vs. max HP.
- Creature gains a ~tempHp : Int~ field; the row 2 HP display shows
  it as a "+N" chip when nonzero.
- The Damage / Heal / Temp HP buttons in card row 3 are wired to a
  shared modal (~viewHpChangeModal~) with two input modes:
  - *Manual*: enter the amount as a number; live preview shows the

  - *Roll dice*: enter a Dice expression (using the same parser as
    the dice modal); Apply rolls and applies in one shot, also
    logging the roll to the dice history (POST /api/dice/history).
- Damage gets an "Ignore temporary HP" checkbox; heal and temp HP
  show only the amount input.

** Initiative manager

- Clicking the blue init-circle on a creature card opens an
  Initiative Manager modal with three sections: *Quick Sort
  Encounter* (re-orders the queue by descending initiative via
  =Encounter.sortByInitiative=), *Auto-roll Initiative* (rolls
  =1d20 + initiativeBonus= for the click target / all / selected
  via =Dice.batchRollCmd=), and *Custom Initiative* (manual value
  apply for target / selected).
- New ~Encounter.sortByInitiative=, ~Encounter.moveUp=, and
  ~Encounter.moveDown= functions.  =activeName= is preserved across
  sorts so re-sorting mid-combat doesn't reset whose turn it is.
- New ~Dice.batchRollCmd= rolls a list of expressions in a single
  Cmd, sharing one timestamp + one sequenced seed-step.  This
  prevents the "8 creatures all roll the same number" collision
  that would happen with N per-call =rollCmd= invocations in the
  same millisecond.

  set per creature (Lyra +5, Brakka -1, Vex/Goblins +2, Shaman
  +1, Sentinel -1, Wisp +3).
- Up / down arrows on each card's left rail now move the creature
  one slot up or down in the queue (via =moveUp= / =moveDown=)
  without touching initiative.  A subsequent =sortByInitiative=
  wipes the manual order — that's the documented contract.
- Selection checkbox in the row 1 left rail is now interactive.
  Plain click toggles a single creature; *Shift+click* selects all
  if any are unselected, deselects all if every creature is
  selected.  Implemented via =preventDefaultOn "click"= so model
  is the single source of truth for the checkbox state.

** Dice source tagging

- =Dice.Roll= gains a =source : Source= field where
  =Source = { feature : String, target : Maybe String }=.  The
  dice history renders a chip per entry — "Damage → Brakka, Ogre
  Brute", "Heal → Lyra Vale (PC)", "Initiative → Goblin Boss",
  "Stat block → Brakka, Ogre Brute".  The chip is hidden for the
  default ~manualSource~ since the dice modal's own buttons make
  the context obvious.
- All ~Dice.*Cmd~ entry points (~rollCmd~, ~advantageCmd~,
  ~disadvantageCmd~, ~coinCmd~, ~batchRollCmd~) take a Source.
  =Dice.rollWithTime= stamps it onto the rolled Roll so callers
  don't have to remember to overwrite afterwards.
- JSON encode / decode round-trip the source.  The decoder uses
  =Decode.oneOf= with =manualSource= as a fallback so legacy
  =dice-history.json= entries from before this field continue to
  load.
- =DiceRerun= preserves the original entry's source so a re-rolled
  "Damage → Brakka" stays labelled the same way.

** Surprise rule (turn skip)

- =Encounter.nextTurn= now honors the per-creature ~surprised~
  flag.  When the queue would make a surprised creature active,
  the creature is skipped and the flag is cleared in the same
  step — their next turn after that happens normally.  A run of
  consecutive surprised creatures all get skipped on one Next
  Turn click.  Defensive iteration cap of ~length creatures~
  guards against an all-surprised queue spinning.  Implemented
  as the first real "beginning of turn" hook composed around
  the existing queue walk.

** Per-creature note

- New ~note : String~ field on =Creature= (10–20 char short label).
  Edited via a small modal opened from the row 1 ✏️ pencil button
  (when empty) or by clicking the note text itself (when set).
  Saving an empty string clears the note.
- Display: the note renders inline next to the name in white
  italics.  The pencil hides as soon as a note exists — the note
  text /is/ the edit affordance.  A muted pipe separator follows
  the note before the AC readout, and another pipe sits after AC
  before the conditions list.
- Modal chrome reuses =.modal-backdrop / .modal/ .modal__header=
  shared with the dice / HP / initiative modals.  Esc, ✕, Cancel,
  and backdrop click all close.

** Death saves engine (5e)

- Replaced the row 2 placeholder ~( Bool, Bool, Bool )~ tracker
  with a real 5e death-save engine.  New
  =Encounter.DeathSaves = { successes : Int, failures : Int }=
  type plus helpers ~emptyDeathSaves~,
  ~addDeathSaveSuccesses~, ~addDeathSaveFailures~,
  ~isDeathSaveStable~, ~isDeathSaveDead~ in =Encounter=.
  ~Encounter.toggleDeathSave~ removed.
- Tracker visibility is keyed exclusively off ~currentHp == 0~.
  No more separate ~inDeathSaves~ flag — that field was deleted
  from =Creature=.  Healing back above 0 hides the tracker; the
  HP-change engine clears the running counts at the same time so
  a re-drop starts fresh.
- Pip layout: a 🌟 prefix label + three success pips, then a 💀
  prefix label + three failure pips, then a 🎲 Roll button and
  the Stable / Dead status badge when applicable.  Pips use the
  star-rating click pattern (clicking pip ~i~ when filled clears
  it and every later one; clicking when empty fills up to and
  including ~i~).
- 🎲 button rolls 1d20 and resolves per 5e:
  - nat 20 → revive at 1 HP, clear tracker
  - 10–19 → +1 success
  - 2–9 → +1 failure
  - nat 1 → +2 failures
  Roll is logged to the dice history with source label
  ~Death save → <creature>~ and persisted server-side via the
  same /api/dice/history pipe as every other roll.
- =Encounter.nextTurn=' s skip loop (renamed
  ~skipUnplayable~) now also skips dead creatures.  Unlike
  surprised, the dead state isn't cleared — the marker just
  walks past every Next Turn.  Cards with three filled failure
  pips get a greyed-out class (~creature-card--dead~) so the GM
  can see TPK members at a glance; pips remain clickable to
  unwind a misclick.
- HP-change engine: ~applyDamage~ is now a clean
  damage-then-clamp; the auto-toggle of any death-save flag
  went away with the field.  ~applyHeal~'s revive path resets
  ~deathSaves~ via ~Encounter.emptyDeathSaves~.
- Seed: Lyra Vale (PC) now starts at 0/42 HP with one failure
  recorded so the tracker is demoed on first load.

** Conditions / effects engine

- Full implementation of the row 3 *Condition/Effect* button.
  ~Creature.conditions~ went from ~List String~ placeholder to
  ~List Condition~ where:
  #+begin_src elm :results none :exports code
  type alias Condition =
      { id : Int
      , name : String
      , note : String
      , duration : Duration
      , saveToEnd : Maybe SaveToEnd
      }

  type Duration
      = DurationManual
      | DurationUntilTurn TurnPhase String     -- "until end of Lyra's turn"
      | DurationCountdown TurnPhase Int Bool   -- N turns; bool = skipNextTick

  type TurnPhase = AtBegin | AtEnd
  #+end_src
- Modal opens from the row 3 button or by clicking any chip.
  Sections (top to bottom): the 15 standard 5e conditions as
  radio buttons (~Encounter.standardConditions~), a custom-name
  text input (typing here overrides the radio), a 10-char note
  input, a duration block (Manual / Until turn / Countdown with
  the relevant sub-controls), and an optional Save-to-end block
  (ability dropdown, DC, bonus, auto-roll toggle).  Edit mode
  surfaces a red Delete button in the footer.
- Live chips on row 1 of the card and in the encounter title bar
  replace the old "Paralyzed | Poisoned" placeholder.  Each chip
  shows ~name (note) 🎲 ⏳N ×~ — click name to edit, click 🎲
  (when a save-to-end is configured) to roll a manual save,
  click × to remove.  ⏱ glyph is shown for ~UntilTurn~ durations
  with the first 4 chars of the reference creature's name.
- Turn lifecycle hooks: =Encounter.nextTurn= now composes
  ~applyEndOfTurn outgoing → skipUnplayable → applyBeginOfTurn
  incoming~.  ~applyEndOfTurn~ ticks ~AtEnd~ countdowns on the
  outgoing creature and expires every ~DurationUntilTurn AtEnd
  <name>~ across the encounter; ~applyBeginOfTurn~ does the same
  for the ~AtBegin~ phase.  Surprised / dead creatures don't get
  begin-of-turn ticks — their turn doesn't actually happen.
- The "skip first end-of-turn tick" rule is honored: when a
  ~DurationCountdown AtEnd~ is created on the currently-active
  creature, the third Bool of the constructor (~skipNextTick~)
  is set so the next end-of-turn pass clears the flag instead
  of decrementing the count.  Means the bearer gets a full
  first turn under the effect.
- Save-to-end auto-roll: =NextTurn= now batches a Cmd per
  active-creature condition with ~saveToEnd.autoRoll = True~,
  using the same ~Dice.rollCmd~ infrastructure.  Result lands
  in =ConditionSaveLanded= which removes the condition on
  ~roll.total >= dc~.  Source label reads
  ~Save: <ABL> DC <N> (<Condition>) → <creature>~ in the dice
  history.

** Dice indicator in encounter controls

- The Encounter Controls panel header gained a small "latest
  roll" cluster left of the existing 🎲 Roll button:
  ~<total> ← 🎲 Roll~.  ~<total>~ is the most recent roll's
  =roll.total= rendered in bold white tabular-nums; the ←
  arrow signals "this number was emitted by the roller."  Both
  hide until the first roll has landed.
- Yellow box-shadow ring on the Roll button whenever a roll
  has landed since the modal was last opened (=DiceUi.unread=
  set by a new ~pushDiceRoll~ helper).  The flag clears on
  =OpenDice=.  All five roll-landing paths (manual dice, HP
  change, initiative batch, death save, condition save) now
  funnel through the same helper so the indicator stays
  authoritative without per-branch bookkeeping.

** Encounter title bar: real status icons + plain-text conditions

- Replaced the placeholder ✊◕🧠🪽 row of state icons in the
  encounter title bar with a live render keyed off the active
  creature's actual flags.  Cover renders ◐ / ◕ / ● for
  half / three-quarters / full (and skips when there's no
  cover); concentrating shows 🧠; hiding shows 👤; flying shows

- The active creature's conditions slot in the title bar

** Auto-scroll active creature card into view

- Each creature card's outer ~<article>~ now carries
  ~id="creature-card-<slug>"~ via a new ~cardId~ helper that
  maps non-alphanumeric chars in the name to underscores.
- New ~scrollActiveIntoViewCmd~ task composes
  =Browser.Dom.getViewport= + =Browser.Dom.getElement=; if the
  active card's bottom is below ~viewport.bottom - 16px~, it
  fires =setViewport= to nudge the page just enough to show
  the card.  Otherwise no-op.
- =NextTurn= and =SetActive= both emit this Cmd so the active
  card is always in view after a turn change or a manual
  scrub.  Result lands in a no-op =ActiveCardScrollChecked=
  Msg.

** Save-to-end auto-roll modes (Manual / Begin / End)

- Replaced the boolean ~autoRoll~ field on
  =Encounter.SaveToEnd= with an =AutoRollMode= ADT
  (=AutoRollManual=, =AutoRollAtBegin=, =AutoRollAtEnd=).  The
  modal's old "Auto-roll at the bearer's begin-of-turn"
  checkbox became three radio buttons stacked vertically.
  Manual is the default when "save-to-end" is first enabled
  (so the GM doesn't get a surprise auto-fire).
- =NextTurn=' s update branch captures the OUTGOING active
  creature's name, runs ~Encounter.nextTurn~, then dispatches
  ~autoRollCmdsFor AutoRollAtEnd outgoingName~ and
  ~autoRollCmdsFor AutoRollAtBegin newActiveName~ on the
  post-state.  Two phases, two Cmd batches, both reading the
  post-tick encounter so already-expired conditions don't
  generate dead saves.

** "Saved: <Condition>" notice on auto-roll success

- New =Encounter.SaveNotice= record (~id~, ~conditionName~,
  ~turnsRemaining~) and a ~saveNotices : List SaveNotice~
  field on =Creature=.  When an AUTO-roll save succeeds, the
  =ConditionSaveLanded= handler captures the condition's name
  before removing it and posts a notice via the new
  ~Encounter.addSaveNotice~ helper.  Manual chip-roll
  successes still remove silently — the chip was visible at
  click time, no narration needed.
- =applyEndOfTurn= ticks each notice down by 1.  Notices start
  at ~turnsRemaining = 1~, so the next bearer end-of-turn
  hook fire clears them.  GM can dismiss earlier via the × on
  the chip (new =SaveNoticeDismiss= Msg).
- View renders the notice as a green chip alongside condition
  chips on row 1 of the card.

** Until-turn target: current vs. next

- New =Encounter.TurnTarget= ADT (=OnCurrentTurn= /
  =OnNextTurn=); ~DurationUntilTurn~ now carries it in
  addition to phase + reference creature.
- ~expireUntilTurn~ refactored from filter to filterMap.
  Matching hook fires drop ~OnCurrentTurn~ conditions
  (expire) and mutate ~OnNextTurn~ conditions to
  ~OnCurrentTurn~ (skip first match).  So
  ~DurationUntilTurn AtEnd OnNextTurn "Lyra"~ is exactly two
  end-of-Lyra fires: first one flips next→current, second
  one expires.
- Modal duration row gained a small
  ~current ⟷ next~ radio toggle between the creature
  dropdown and the word "turn".  When phase = Begin and the
  reference creature is the currently-active creature, the
  "current" radio is grayed (~cond-phase--disabled~) and the
  =repairUntilTarget= helper auto-flips
  ~OnCurrentTurn~ → ~OnNextTurn~ on phase / creature changes
  that would otherwise leave the form in an invalid state.

** Card row 3: dice removed, memo, alarm-clock timer, ping audio

- Removed the row 3 🎲 placeholder button.  Was inert.
- New ~memo : String~ field on =Creature= with a 20-char cap.
  Empty memo renders as the existing 📝 button (clicking opens
  the new memo modal).  Non-empty memo replaces the icon with
  a white-text pill plus an × to clear.  Click the text to
  re-edit; click × to clear (which restores the 📝 icon).
- New ~timer : Maybe Timer~ field where
  ~Timer = { remaining : Int, phase : TurnPhase, ringing : Bool }~.
  No timer → existing ⏱ button (clicking opens the timer
  setup modal: count 1..99 + begin / end phase toggle).
  Counting → pill shows the remaining number + ×.
  Reaches 0 → ringing flag flips on, pill turns red, the count
  flashes via a CSS keyframe animation, and a page-level
  ~<audio src="/ping.wav" autoplay>~ mounts to play the ping
  sound once.
- =applyEndOfTurn= and =applyBeginOfTurn= each gained a
  ~tickTimerFor~ step.  Timers in the matching phase
  decrement by 1 per tick; once ringing, no further ticks
  (the GM dismisses via ×).
- New ~public/ping.wav~ — 700 ms 880 Hz sine with 50 ms fade
  in / out, 22050 Hz mono 16-bit.  Generated locally via
  Python's stdlib ~wave~ module.

** Apply-to-selected scope on HP and condition modals

- =HpChangeUi= and =ConditionUi= each gained a
  ~applyToSelected : Bool~ field plus a toggle Msg.  When the
  GM has at least one creature checked in the queue, both
  modals render an "Apply to all selected creatures (N)"
  checkbox.  Hidden when the selection is empty (no useful
  no-op surface).
- HP path: ~applyHpChangeAndClose~ folds the engine over the
  resolved target list (single ~ui.target~ when off, all
  ~.selected~ creatures when on).  Dice mode rolls ONCE and
  shares the total across all targets — 5e Fireball
  semantics, with a caption in the modal explaining so.  The
  dice-history Source's ~target~ string joins the names so
  the log entry reads honestly.
- Condition path: ~commitCondition~ now folds
  =Encounter.addCondition= over the resolved target list.
  Each selected creature gets its own fresh ~id~, so
  durations and pip strips are independent.  Hidden in edit
  mode — you're modifying one specific row, not splatting.

** Card right rail: remove + duplicate, no minion

- Removed the 👿 placeholder button.  Was inert.
- × button is now wired: =RemoveCreature name= →
  ~Encounter.removeCreature~.  If the removed creature was
  the active one, the marker advances to their successor (or
  the first creature if they were last); empty queue leaves
  ~activeName = ""~ and the title bar's ~Maybe~-aware
  rendering shows "—".
- ⧉ button is now wired: =DuplicateCreature name= →
  ~Encounter.duplicateCreature~.  Inserts a clone immediately
  after the source in the queue.  Name gets a ~(copy)~ /
  ~(copy 2)~ / ~(copy 3)~ suffix (uniquified against the
  existing names).  Conditions and save notices are copied
  but with freshly-allocated encounter-wide ids so edits on
  the original's chips don't clobber the duplicate's.
  ~selected~ is forced to ~False~ on the copy so a
  multi-target action right after duplication doesn't
  accidentally splatter both copies.
