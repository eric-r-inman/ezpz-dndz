#+title:     Changelog
#+language:  en

* Upcoming

** Architecture

- Split the Elm frontend into two modules: ~Encounter.elm~ (domain
  layer — types, seed data, turn logic) and ~Main.elm~ (application
  shell + view code).  Domain code does not import rendering
  primitives.  See [[file:docs/ARCHITECTURE.md][docs/ARCHITECTURE.md]] for the full discussion and
  the discipline that goes with it.

** Frontend

- Introduce real turn tracking.  =Encounter.nextTurn= advances the
  active creature in initiative order and increments =round= on wrap.
  Wired to the *⏭ Next Turn* button in Encounter Controls.
- Encounter title bar shows live =round=, active creature name, and
  active creature HP (state icons and the conditions summary stay
  placeholder for now).
- Brand mark dropped; title renders as "eZpZ-dndZ" in plain text
  rather than the gradient mark + wordmark.
- Right-arrow on a creature card now jumps the active marker to that
  creature without advancing the turn (no round bump, no turn-
  progression hooks).  Wires =Encounter.setActive=, distinct from
  =Encounter.nextTurn=.

** Dice roller

- New ~Dice.elm~ domain layer: notation parser (=1d6=, =2d8+3=,
  compound =1d8 + 2d6=, damage-tagged =2d6+3 fire damage=, and the
  stat-block average wrap =7 (1d8 + 3)=); random-roll generators for
  standard / advantage / disadvantage / coin; bounded in-memory
  history (max 30, matching the JS roller).
- New dice modal in =Main.elm=, wired to the existing *🎲 Roll*
  button.  Free-text expression input with Enter-to-roll, count and
  modifier sliders, rainbow d4–d100 face buttons, advantage /
  disadvantage / coin-flip, history list with re-roll and clear.
  Closes on backdrop click, ✕, or Esc.
- Stat-block traits in the Compendium now have clickable inline
  dice notation (=Dice.scan= splits text into literal runs and
  recognized formulas); clicking rolls the formula and opens the
  modal in one gesture.
- Server-side history persistence so the dice log survives reloads
  without any handwritten JS.  =GET / POST / DELETE /api/dice/history=
  are handled in =crates/server/src/dice.rs=, persisting to
  =dice-history.json= (configurable via =--dice-history-path=) with
  atomic-rename writes and an async mutex around the file.
